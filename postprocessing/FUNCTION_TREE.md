## Relationship to Daniel's `codes` version

`main_unified_paper_sweep.py` does not import or execute `main.py` or
`main_simple.py`. The statement at its end,

```python
if __name__ == "__main__":
    main()
```

calls the unified driver's own `main()` function. That function orchestrates
the existing solver modules directly. It also selects `spsolve` or ASM-CG inside
`solve_trace_system()` instead of calling the older `solve_reduced_system`
wrapper, thereby avoiding its hard-coded solver selection.

Compared with `/home/jurrutia/playground_Daniel_clean/codes`, the following
files used by the final sweep are byte-for-byte identical:

- `hdgCommon/hdg_preprocess.py`;
- `referenceElement/createReferenceElementTri.py`;
- `solver/compute_elements_solution_gpu.py`;
- `solver/post_processing_new.py`;
- `solver/preconditioners/additive_schwarz.py`;
- `solver/dense_blocks/matvec.py`;
- `Utilities/computeL2Norm.py`;
- `Utilities/computeL2NormPostProcessed.py`.

The changed files are limited and have specific purposes:

- `solver/compute_projection_faces.py` evaluates the non-polynomial exact
  solution instead of the polynomial patch solution `x**2` on the boundary;
- `solver/numerical_integration.py` evaluates the corresponding non-polynomial
  source term instead of the constant source `-2`;
- `poisson/analyticalPoisson.py` and `poisson/sourcePoisson.py` define the same
  manufactured problem for diagnostics;
- `solver/matrix_assembly.py` adds an optional `HDG_LOCAL_SNAPSHOT` diagnostic.
  It is inactive unless that environment variable is explicitly set and does
  not change the assembled equations in the reported runs;
- `paper_diagnostics.py` and `main_unified_paper_sweep.py` are new paper-facing
  orchestration and verification files.

Thus the core reconstruction, postprocessing, ASM preconditioner and dense-block
matrix-vector kernels are Daniel's existing implementations. The numerical
integration source kernel necessarily contains a different formula because the
paper uses a different manufactured solution. Corrected reference-node meshes
for `p=3,4` are a data correction, not a kernel rewrite.
